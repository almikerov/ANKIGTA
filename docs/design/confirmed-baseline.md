# ANKIGTA — Confirmed Baseline

> Status: confirmed design baseline. The user has reconfirmed that decisions marked accepted in the source interview are valid even where the exported transcript omitted the intervening reply. Product decisions are complete enough for `/to-spec`; remaining technical uncertainties become explicit blocking tests and acceptance gates.

## Product intent

- Связать обучение в Anki с пространством MTA:SA.
- Привязывать учебные цели Anki к сущностям игрового мира.
- Открывать учебный материал при приближении или по кнопке.
- Передавать пользовательскую оценку обратно в Anki.
- Использовать пространственное расположение сущностей как часть запоминания.

## Explicitly confirmed behavior

### Managed world

- Поддерживаемые Map Entity включают object, vehicle и ped, созданные через Map Editor.
- Каждой Map Entity автоматически назначается постоянный ID, сохраняемый через проверяемое сохранение карты.
- Activation Zone и маркер следуют за текущим положением движущейся Runtime Instance.
- Уничтожение Runtime Instance убирает активную зону и маркер, но не удаляет Spatial Link.
- ANKIGTA не управляет респавном.
- В F7 должны оставаться видимыми все управляемые сущности загруженных карт; для недоступной Runtime Instance сохраняется исходная позиция из карты.
- Действие выбора сущности в мире называется `Pick Entity`, а не `Pick object`.
- Pick Entity временно скрывает F7, разрешает движение и обзор, но блокирует стрельбу, вход в транспорт и обычные взаимодействия.
- Левая кнопка выбирает первую видимую управляемую Runtime Instance под прицелом; выбор сквозь стены запрещён, а отдельного лимита расстояния сверх клиентской прогрузки нет.
- Неуправляемый элемент или сущность вне загруженной карты не выбирается, и интерфейс показывает причину. Уничтоженные и непрогруженные сущности выбираются только через список F7.
- `Esc` отменяет Pick Entity. После успеха F7 открывается на выбранной Map Entity; при успехе, отмене или сбое восстанавливаются прежние управление и курсор.

### Player scope

- ANKIGTA является однопользовательским продуктом для администратора MTA.
- Study Player — вошедшая учётная запись с административным правом в MTA ACL.
- Только Study Player видит F7, HUD, карточки, Activation Zone и маркеры; сервер отклоняет события ANKIGTA обычных игроков.
- Только Study Player связан с единственной локальной коллекцией Anki и companion add-on.
- Обычные игроки не создают и не видят собственные Spatial Link или карточки ANKIGTA.
- Независимые коллекции, личные связи и многопользовательский учебный режим не поддерживаются и не планируются.
- Если другие игроки всё же находятся на сервере, они могут перемещаться пассажирами при Teleport, а Review Protection занятого автомобиля косвенно защищает пассажиров; это не считается multiplayer study support.

### Radius and activation

- Начальное значение радиуса для новой сущности копируется из текущей глобальной настройки; последующее изменение глобального значения не переопределяет уже созданную сущность.
- Подтверждённое начальное значение по умолчанию — 3 метра.
- Допустимый диапазон — 0,5–50 метров с шагом настройки 0,5 метра.
- Значение вне диапазона отклоняется с понятной ошибкой, а не исправляется молча.
- Нулевой радиус запрещён, потому что ручная кнопочная активация также зависит от нахождения внутри зоны.
- `Activation Zone` означает физическую сферу в мире; отметка на миникарте называется `Minimap Blip`.
- Задержка автоматического открытия — глобальное числовое поле в секундах, без индивидуальных значений у Map Entity.
- Значение задержки по умолчанию — 1 секунда; допустимы значения от 0 до 60 включительно и до двух знаков после запятой.
- Нулевая задержка означает немедленное открытие. Пустые, отрицательные, нечисловые и выходящие за диапазон значения отклоняются с понятной ошибкой.
- Выход из всех подходящих Activation Zone отменяет отсчёт; во время отсчёта ближайшая подходящая сущность постоянно пересчитывается.
- Для автоматического открытия в автомобиле всегда действует настраиваемый порог скорости: `0` требует полной остановки, `10000` практически снимает ограничение и является значением по умолчанию.
- `Show radius` у Map Entity постоянно показывает её Activation Zone, пока Runtime Instance доступна и находится в текущих `interior/dimension`.
- Next Card Indicator задаётся dropdown с тремя режимами: `Show sphere and minimap`, `Show minimap only`, `Show nothing`.
- Значение Next Card Indicator по умолчанию — `Show nothing`.
- Отдельного режима `Show sphere only` нет.
- Режим `Show sphere and minimap` временно показывает Activation Zone следующей цели независимо от её `Show radius`.
- Если постоянный и временный показ совпадают, рисуется одна сфера с акцентным цветом и мягкой пульсацией вместо нейтрального оформления.
- Визуальная сфера не создаёт отдельную Activation Zone и не меняет радиус.
- Если следующая карточка связана с несколькими сущностями, Next Card Indicator отмечает только ближайшую подходящую сущность.

### Maps and world contexts

- По умолчанию корректная загруженная карта включена в обучение.
- Для каждой карты сохраняется переключатель `Include in study`.
- Очередь обучения не ограничивается текущими interior и dimension: к цели можно телепортироваться.
- Activation Zone, автоматическое открытие, кнопочная активация и список ближайших сущностей работают только в текущих interior и dimension игрока.
- Смена interior или dimension отменяет ожидающее автоматическое открытие, но не прерывает уже открытое повторение.

### Teleport

- Teleport выполняется напрямую, без поиска безопасной точки.
- Разрешён перенос в воду, пустоту, коллизию или автомобиль.
- Если игрок находится в автомобиле, переносится автомобиль со всеми пассажирами.
- Для уничтоженной или иначе недоступной сущности Teleport использует исходную позицию из карты и не получает отдельную специальную подпись.

### Anki integration

- Server-side Lua — единственный шлюз MTA к привилегированному companion control API. Этот путь подтверждён на настоящем MTA Server 1.6 build 24124 через `fetchRemote` и numeric IPv4 loopback.
- CEF не имеет рабочего доступа к rating, scheduler, collection operations, постоянному connection token или companion control API. Stock MTA показывает карточному JavaScript объект `window.mta`, но native `isLocal` guard отклоняет его привилегированный dispatch из remote browser; наличие этого неработающего stub принято для v1. Для точного предъявления уже допущенной карточки CEF напрямую загружает HTML и media через отдельный read-only loopback content endpoint по короткоживущей capability URL одного render.
- Companion add-on — единственный координатор Review Transaction; Anki остаётся единственным владельцем расписания.
- Companion add-on оценивает карточку только после того, как штатный планировщик Anki признал её scheduler-admitted; он не изменяет приватную очередь и не создаёт собственный admission-механизм.
- Spatial Link указывает на Anki Card Identity: `collection identity + cardId`.
- Collection identity хранится как add-on-owned UUID в collection config. При обнаружении копии пользователь выбирает `Это прежняя коллекция` либо `Это новая копия`; новая копия получает новый UUID и не наследует Spatial Link. Безопасное значение по умолчанию — новая копия.
- Если прежний экземпляр с UUID всё ещё зарегистрирован на компьютере, обнаруженный дубликат автоматически считается новой копией. Сохранить прежнюю identity можно только для переноса/восстановления, когда старый экземпляр больше не найден.
- Пользователь явно выбирает единственную Bound Anki Collection и сам открывает соответствующий профиль в Anki. При другой открытой коллекции обучение приостанавливается; связи и оценки туда не переносятся.
- Одна Map Entity связывается не более чем с одной карточкой; одна карточка может использоваться несколькими Map Entity с предупреждением о повторном использовании.
- Оценка идемпотентна по `reviewTransactionId`.
- Anki, companion add-on и MTA Server в v1 работают на одном компьютере.
- ANKIGTA не запускает Anki Desktop и не переключает профиль; пользователь делает это сам.
- Companion add-on пользователь устанавливает и обновляет самостоятельно. ANKIGTA не изменяет каталог add-on, не показывает команду установки и не перезапускает Anki ради обновления.
- Отдельной проверки версии companion add-on и экрана совместимости нет; отсутствие ответа обрабатывается как обычная ошибка соединения.
- Если Anki не запущена либо закрылась после соединения, ANKIGTA восстанавливает игровые управление и звук, приостанавливает обучение и просит пользователя открыть Anki.
- После ручного открытия Anki Companion Connection восстанавливается автоматически. В отключённом состоянии также всегда доступна кнопка `Подключиться` для немедленной ручной попытки.
- Переподключение не возобновляет обучение: после сверки транзакций ANKIGTA остаётся на паузе без filtered deck и пространственных активаций, пока пользователь сам не запустит обучение.
- Настоящая rescheduling filtered deck `ANKIGTA Session` прошла compatibility-прототип на Anki 26.05; поддержка остаётся ограниченной явно протестированными версиями.
- v1 ограничена Windows, FSRS и явно протестированным диапазоном версий Anki Desktop.
- Порт и токен имеют соответствующие настройки на обеих сторонах: companion add-on слушает и проверяет, MTA Server подключается и предъявляет.
- Токен необязателен. При его отсутствии работа разрешена, но показывается закрываемое предупреждение.
- По умолчанию при первой настройке ANKIGTA автоматически генерирует токен и настраивает его на обеих сторонах без ручного копирования. Пустой токен возможен только после явного отключения защиты.
- Companion add-on является владельцем автоматически создаваемых порта и токена. После однократного выбора пользователем папки MTA-ресурса add-on атомарно публикует локальный connection file, а MTA Server только читает его.
- В дополнительных настройках внутри companion add-on и MTA имеются поля для ручной замены порта и токена. Существующий токен не показывается открытым текстом; пользователь может ввести только новое значение.
- Ввод ручного порта или токена включает Manual Connection Mode на соответствующей стороне. Автоматика не перезаписывает manual override. При несовпадении effective config соединение не устанавливается и показывает явную ошибку; пользователь вручную согласует обе стороны либо явно возвращает обе в Automatic Connection Mode.
- v1 доверяет локальному Windows-компьютеру и всем его программам. Токен защищает только от случайных запросов и отделяет карточный CEF от control API; он не обещает защиту от локального администратора или вредоносного процесса. Специальное шифрование connection file не требуется, но токен не показывается в обычном UI и логах.
- Automatic connection config хранит одну предыдущую подтверждённо рабочую версию. Новая версия записывается через temporary file и atomic replace; MTA проверяет format/version/protocol identity. При повреждённой или неподтверждённой новой версии используется предыдущая, а пользователь видит ошибку применения настроек. Если обе версии непригодны, соединение остаётся отключённым.
- Companion add-on в v1 слушает только numeric IPv4 loopback `127.0.0.1`; этот путь подтверждён, а доступ через LAN-адрес отвергнут. IPv6 `::1` оказался несовместим с проверенным MTA HTTP path и в v1 не поддерживается. Подключения с других компьютеров, из LAN или интернета запрещены независимо от токена.
- Свободный loopback-порт выбирается и настраивается на обеих сторонах автоматически; при конфликте ANKIGTA выбирает новый. Ручной порт доступен только в дополнительных настройках.
- Выбор нового свободного порта и ручной override подтверждены disposable-прототипом, но атомарное сохранение и публикация production connection config между add-on и MTA Server ещё не доказаны.
- HTTP `200` не считается достаточным подтверждением операции: принимающая сторона проверяет Content-Type, JSON envelope, обязательные поля и совпадение `requestId`/`reviewTransactionId`.
- Обычный control request ждёт не более 5 секунд. Read-only request после временной ошибки автоматически повторяется один раз с тем же `requestId`; rating не повторяется вслепую и сверяется по исходному `reviewTransactionId`.
- Перестройка `ANKIGTA Session` имеет отдельный предел 30 секунд и показывает прогресс. После timeout интерфейс освобождается, а automatic reconnect продолжается в фоне без автоматического запуска обучения.
- Отдельной кнопки `Test connection` нет: после неудачного подключения причина показывается автоматически.
- Кнопка `Подключиться` является действием установки соединения, а не отдельным диагностическим `Test connection`; автоматическое переподключение при этом сохраняется.
- Anki является источником истины для текста и полей note, шаблонов, CSS, медиа, Anki Tag, колоды, расписания и состояний suspended/buried.
- ANKIGTA является источником истины для Spatial Link и игровых метаданных Map Entity; Entity Tag и Anki Tag — разные понятия.
- При подключении и после уведомления companion add-on изменения Anki обновляются автоматически; перед открытием карточки запрашиваются актуальные render и scheduler state.
- Перемещение карточки между колодами и изменение её текста, шаблона или Anki Tag не ломает Spatial Link.
- Встроенный выбор колоды задаёт только начальный Card Picker Deck Filter. Он не ограничивает `ANKIGTA Session` и не становится свойством уже созданной связи.
- Удалённый `cardId` становится `Card missing`; новый `cardId`, созданный Anki, автоматически не сопоставляется и требует `Replace card`.
- Из ANKIGTA обратно в Anki передаются только оценки.
- Большое обновление Anki обрабатывается в фоне с прогрессом и не блокирует F7.

### Prototype 0001 result

- Канонический результат находится в `docs/prototypes/0001-exact-card-idempotent-review.md`; verifier доказательств проходит.
- Общий verdict — `failed`: на Anki Desktop 26.05 с V3 scheduler и FSRS точную non-top Card X можно загрузить и отрендерить, но штатная оценка отклоняется ошибкой `not at top of queue`, пока scheduler-next — Card Y.
- Ошибка происходит до изменения карточки и до создания `revlog`.
- Для scheduler-top карточек отдельно подтверждены Again, Hard, Good и Easy, одна запись `revlog`, неизменяющий identical retry, конфликтующий retry и сверка потерянного ответа в одном процессе.
- Идемпотентность после перезапуска процесса не доказана.
- Prototype-owned collection UUID не является доказанным production collection identity.
- Private queue mutation, прямой SQL, собственный scheduler и retry после scheduler exception запрещены как обход.
- Prototype 0001 сам по себе ничего не доказал о filtered deck; отдельный gate впоследствии закрыт успешным Prototype 0002.

### Prototype 0002 result

- Канонический результат находится в `docs/prototypes/0002-filtered-deck-fsrs-admission.md`; verifier доказательств проходит, общий verdict — `passed`.
- На Anki Desktop 26.05 с V3 scheduler и FSRS настоящая rescheduling filtered deck `ANKIGTA Session` штатно создаётся из точного набора `cardId`.
- Порядок `cardId` в полном наборе не задаёт scheduler-top. Для выбранной non-top Card X подтверждён Exact Card Admission: X-only rebuild той же owned filtered deck → наблюдение X как scheduler-top → оценка через Anki → rebuild полного набора.
- Для new, learning, relearning, due review и future review все четыре оценки совпали с контрольным Anki Reviewer в 20 сравнениях с допустимой временной погрешностью; каждая оценка создала ровно один `revlog`.
- Suspended и buried карточки не допускаются к оцениванию и остаются Preview only.
- Learning/relearning lifecycle, rebuild между повторениями, pause/stop, возврат в исходные колоды, защита от коллизии имени и проверенные recovery boundaries прошли без лишних `revlog` и повреждения расписания.
- Не доказаны сбой внутри атомарной backend-перестройки, durable production Review Transaction journal и стабильная production collection identity.
- Опровергнуты два предположения: exact-ID input order не управляет scheduler-top; exact filtered deck не сохраняет автоматически исходный дневной лимит новых карточек.
- Обход исходного дневного лимита принят как намеренное поведение: все связанные новые карточки доступны, а карточка сверх сегодняшнего лимита Anki получает предупреждение в Review Mode.

### Prototype 0003 result

- Канонический результат находится в `docs/prototypes/0003-companion-lifecycle-recovery.md`; verifier доказательств проходит, общий verdict — `partially passed`.
- Durable Review Transaction recovery прошёл на проверенных границах: до scheduler call, после Anki commit до сохранения результата и после durable result до восстановления сессии.
- Ключ журнала — `collection identity + reviewTransactionId`. Identical retry после перезапуска возвращает прежний результат; изменение коллекции, карточки или оценки отклоняется без мутации.
- Уже применённая оценка обнаруживается без второй scheduler invocation; доказанно непринятая доотправляется ровно один раз.
- `Outcome Unknown` переживает перезапуск, не вызывает слепой retry, блокирует только затронутую карточку и запрещает переключение коллекции и восстановление filtered deck до разрешения.
- `revlog` timestamp не является надёжным transaction ID; reconciliation требует единственного coordinator и полного before/after card, FSRS и `revlog` delta.
- Два профиля действительно могут иметь одинаковый числовой `cardId`. Add-on-owned UUID в collection config различал их и пережил перезапуск и переименование, но нативный UUID и production copy/clone/import policy не доказаны.
- A → B → A технически прошёл через stock non-private AQT lifecycle, однако документированного add-on API переключения профиля в Anki 26.05 не найдено.
- Закрытие неоценённого standard Reviewer из question/answer прошло быстро и без мутации, но использованный AQT surface version-sensitive и не документирован как add-on API.
- Немедленный cleanup Reviewer после начала асинхронной оценки не прошёл safety-gate: backend применил Good один раз, но штатный callback продолжал зависеть от уже очищенного `Reviewer.card`.
- Не внедрялось завершение процесса внутри атомарной backend answer/rebuild операции; нативного Anki commit receipt с `reviewTransactionId` нет.
- Опровергнуты предположения, что profile name/path является identity, non-private API автоматически поддерживается, закрытие UI отменяет rating и немедленный cleanup во время rating безопасен.

### Prototype 0004 result

- Канонический результат находится в `docs/prototypes/0004-mta-loopback-transport.md`; read-only verifier проходит, общий verdict — `partially passed`.
- На настоящем MTA Server 1.6 release build 24124 server-side Lua через `fetchRemote` надёжно обменивался запросами с disposable companion harness по numeric IPv4 loopback `127.0.0.1`. Client-side Lua и CEF в сетевом пути не участвовали.
- Listener, привязанный к `127.0.0.1`, был недоступен через LAN-адрес. Правильный, неправильный и отсутствующий токен дали ожидаемые результаты; секрет не попал в evidence и логи. Явно отключённая защита технически работала только в предупреждающем режиме.
- IPv6 `::1` не прошёл: рабочий Windows listener был доступен локальному Python-клиенту, но MTA `fetchRemote` завершался status `6`, не достигая harness. Внешний интерфейс как fallback не использовался.
- Отсутствие companion, его исчезновение во время запроса, медленный или повреждённый ответ, resource restart и MTA restart завершались ограниченно по времени и не запускали обучение автоматически. Ручная кнопка `Подключиться` и автоматическое переподключение восстановили связь, сохранив паузу.
- Потеря ответа и перезапуски сохраняли исходные `requestId` и `reviewTransactionId`. Идентичный повтор возвращал сохранённый результат; конфликтующий повтор отвергался; одна логическая rating-операция не превращалась в две.
- Transport error и даже HTTP `200` сами по себе не определяют результат Review Transaction. Требуются проверка protocol envelope и сверка по исходному `reviewTransactionId`; неопределённый исход остаётся `Outcome Unknown`.
- Параллельные read-запросы не смешивали callbacks и IDs. Rating-запросы были сериализованы в одном coordinator queue, отдельно от чтений.
- Автоматический выбор следующего свободного порта, protocol identity и ошибки ручного override подтверждены. Production-механизм атомарной публикации общей конфигурации между независимыми хранилищами не проверялся.
- Payload до 2 MiB прошёл в этой среде, но универсальный безопасный предел, production timeout/retry policy, backpressure и latency SLA не установлены.
- Общий verdict остался частичным из-за post-run safety deviation: после канонического изолированного запуска официальный MTA installer повторно использовал существующий каталог `C:\Games\MTA San Andreas 1.6`, а pre-action hash manifest отсутствовал. Это не затронуло канонический transport run или данные Anki, но не позволяет доказать byte-for-byte отсутствие внешних изменений.
- Опровергнуты предположения, что IPv4-успех автоматически означает поддержку `::1`, HTTP `200` автоматически означает protocol success и `abortRemoteRequest=true` гарантирует callback на проверенном MTA build.

### Prototype 0005 result

- Канонический результат находится в `docs/prototypes/0005-map-editor-identity-persistence.md`; read-only verifier проходит, общий verdict — `failed`.
- Отдельный sandbox MTA Server, disposable resource и настоящий MTA Map Editor UI были запущены, но runtime остановился до создания или сохранения disposable map. S1–S18 остались `not_run`; S19 выполнен частично с полным восстановлением внешних client config/log изменений по pre-run SHA-256.
- Для `object`, `vehicle` и `ped` подтверждён штатный serialization path: `ankigtaEntityId` может храниться как element data/EDF property.
- Произвольный `ankigtaMapId` на корне `<map>` stock Editor не сохраняет при round-trip. Поддерживаемый map-metadata path — отдельный EDF custom child element.
- `cloneElement` копирует custom data, `copyResource` копирует embedded IDs, а `renameResource` сохраняет их. Stock Editor не предоставляет identity-aware collision handling или reidentity.
- Не найден публичный Editor contract, одновременно подтверждающий окончание save, устойчивую запись и независимый read-back. Не найдены dirty-state/external-change check, hash/mtime compare или compare-and-swap.
- Штатный save lifecycle удаляет прежний `.map`, создаёт и сохраняет новый пустой `<map>`, затем выполняет итоговую сериализацию. Низкоуровневый XML writer имеет temp/backup recovery, но вся Editor save transaction не атомарна.
- Принятые продуктовые правила `Pending Map Save`, независимого read-back и блокировки неоднозначной identity сохраняются, но не обеспечиваются stock Editor самостоятельно. Фоновая XML-запись не использовалась и не принимается как обход.

### Prototype 0006 result

- Канонический результат находится в `docs/prototypes/0006-cef-card-content-isolation.md`; read-only verifier проходит, общий verdict — `failed`.
- Disposable read-only content endpoint подтвердил numeric IPv4 bind/Host check, 256-bit per-render capability, привязку к collection/card/side/generation, expiry/revocation, uniform denial, Range, ограничения запросов/объёма и bounded concurrency. Это результат harness, а не доказательство поведения real MTA CEF.
- В reference source `window.mta` добавляется во все V8 contexts без local/remote проверки. Native `isLocal` guard блокирует привилегированный dispatch из remote browser, но принятое строгое обещание отсутствия card-visible MTA bridge не выполняется.
- Stock MTA использует один domain allow-state для external subresources и main-frame navigation. Разрешение домена для image/font/CSS/script одновременно разрешает переход main frame; Lua notification не может отменить его до запроса.
- Native popup path блокирует popup и видит `user_gesture`, но Lua получает только target/opener. Resource не может доказуемо отличить genuine click от script-only вызова и реализовать принятое открытие только пользовательской ссылки в системном браузере.

- После результата принят stock-MTA fallback: ANKIGTA не требует native/upstream fork, принимает card-visible неработающий `window.mta` stub, не обещает раздельную блокировку main-frame navigation и не обещает system-browser handoff. Сохраняется фактическая граница: remote card content не может выполнить привилегированную MTA/Anki операцию.

### Review experience

- Стандартный поток: question → reveal answer → Again/Hard/Good/Easy.
- Supported Card отображается во внутреннем stock MTA CEF в режиме best effort. ANKIGTA передаёт HTML, CSS, JavaScript и media references без намеренного удаления содержимого, но не обещает пиксельное или полностью поведенческое совпадение с Anki Desktop.
- Привилегированные операции проходят только через server-side Lua. HTML и media уже допущенной карточки CEF загружает напрямую через отдельный read-only content endpoint add-on; endpoint не умеет оценивать карточки или обращаться к расписанию и использует короткоживущую capability вместо постоянного connection token.
- Control JSON имеет предел 2 MiB и не содержит тяжёлые media. Общий размер карточки этим пределом не ограничен; точные streaming, range, cache и per-media limits определяются CEF-прототипом с обязательной проверкой rendering fidelity.
- Карточный CEF может загружать внешние HTTP(S)-ресурсы, включая изображения, шрифты, стили и скрипты, через штатные domain permissions MTA. Этот доступ не даёт рабочего privileged dispatch, companion control API, connection token или capability другой карточки.
- Stock MTA может разрешить main-frame navigation карточной поверхности на домен, уже разрешённый для фоновых ресурсов. Верхний Review Mode остаётся отдельной оболочкой, но ANKIGTA не обещает предотвратить такой переход до запроса и не открывает пользовательские ссылки автоматически в системном браузере Windows. Popup остаётся заблокирован штатным MTA; downloads и поведение сторонней страницы не входят в поддерживаемый контракт v1.
- После такого перехода Review Mode показывает External Card Page, но оставляет Again/Hard/Good/Easy доступными. `Вернуться к карточке` заново загружает текущую сторону Anki Card и не является условием оценивания.
- Визуальные и поведенческие отличия, явная ошибка загрузки, ошибка HTML/JavaScript/шаблона, отсутствующее медиа и External Card Page не блокируют оценивание. Review Mode показывает предупреждение и оставляет решение об оценке пользователю.
- Для новой карточки сверх сегодняшнего лимита исходной колоды Review Mode показывает предупреждение `Новая карточка вне сегодняшнего лимита Anki`; карточка при этом остаётся доступной для обычной оценки.
- `Suspended` и `Buried` карточки сохраняют Spatial Link и отображаются в F7 с соответствующим статусом.
- Такие Unavailable Card исключаются из `ANKIGTA Session`, статистики и маркера следующей карточки; автоматическая активация для них не запускается.
- Ручная активация Unavailable Card открывает только Preview only без Again/Hard/Good/Easy; not-due policy не может разрешить их оценивание.
- Not-due Card по умолчанию также открывается только как Preview. Настройка `Разрешить досрочное повторение` включает штатную early-review оценку через Anki и предупреждение о том, что срок ещё не наступил.
- При включённом досрочном повторении Not-due Card входит в `ANKIGTA Session`, получает Activation Zone и Next Card Indicator и может открываться автоматически; при выключенном — исключается из сессии и автоматической активации.
- После снятия статуса `Suspended` или `Buried` в Anki карточка автоматически возвращается в обычный поток.
- Review Mode является модальным: `Esc` всегда закрывает его без новой оценки, а `F7`, `E`, `1–9`, `+` и `-` не выполняют игровые действия ANKIGTA.
- Если оценка уже отправлена, закрытие интерфейса не отменяет её: Review Transaction завершается или сверяется в фоне.
- Запрос переключения профиля закрывает открытую карточку без изменений, если оценка ещё не отправлена. После отправки оценки переключение ждёт автоматического завершения Review Transaction.
- Потеря фокуса или `Alt+Tab` не закрывает карточку и не оценивает её; после возврата интерфейс просит нажать на окно для восстановления фокуса.
- Review Protection и блокировка управления сохраняются до закрытия Review Mode.
- При закрытии восстанавливается точное прежнее состояние управления и звука, а не выполняется безусловное включение.
- Уже начатое повторение разрешается завершить при выгрузке карты, разрушении сущности или изменении Spatial Link; затем очередь, статистика и маркеры пересчитываются.
- При отключении Anki загруженный материал остаётся видимым, оценка блокируется, а окно всегда можно закрыть.
- При подключении к другой коллекции оценка текущей карточки блокируется.
- Досрочное повторение изменяет расписание только средствами Anki; если выбранная версия Anki не может сделать это безопасно, карточка становится Preview only.
- Карточный контент не получает работающего privileged dispatch к MTA или companion API; видимый stock-MTA `window.mta` stub допускается. Ошибка или неподдерживаемое поведение шаблона показывается как предупреждение и не блокирует оценивание.
- `Review Protection` отделён от `Disable player controls`.
- При включённой Review Protection игрок и занятый им автомобиль не получают новый урон; защита не замораживает игру и не восстанавливает ранее потерянное здоровье.
- `Review Protection` и `Disable player controls` включены по умолчанию.
- `Close after rating` — булева настройка. При включении окно закрывается после любой принятой оценки, включая Again.
- Отсутствующий отдельный медиафайл, небезопасный или полностью сломанный шаблон показывают заглушку/предупреждение, но не блокируют оценивание; решение об оценке остаётся пользователю.
- Аудио текущей стороны воспроизводится как в Anki; звук карточки и заглушение игрового мира управляются раздельно.

### Session lifecycle

- После запуска Anki сначала устанавливается Companion Connection. Временная filtered deck `ANKIGTA Session` создаётся или восстанавливается после подключения только при активном обучении.
- Первоначальное подключение не начинает обучение автоматически. Пользователь явно нажимает `Начать обучение`; только после этого создаётся `ANKIGTA Session`, включаются пространственные активации и маркер.
- Стандартный Anki Reviewer и обучение ANKIGTA взаимоисключающие. Запуск обычного повторения в Anki ставит ANKIGTA на паузу, безопасно завершает уже отправленную Review Transaction и очищает filtered deck.
- После обычного Anki Reviewer игровое обучение не возобновляется автоматически; пользователь снова нажимает `Начать обучение`.
- Если Reviewer уже открыт при нажатии `Начать обучение`, неоценённый question/answer закрывается без мутации через протестированный version-sensitive AQT surface. При уже начатой оценке показывается `Завершаем оценку Anki…`; Reviewer закрывается и `ANKIGTA Session` создаётся только после штатного callback. Зависший callback блокирует запуск сессии и не обходится принудительным cleanup.
- Изменения Active Map Set и Spatial Link применяются между открытыми повторениями.
- Обычная `ANKIGTA Session` содержит полный рассчитанный набор. Для ручного открытия выбранной доступной Card X companion add-on временно перестраивает owned filtered deck в X-only набор, проверяет X как scheduler-top, завершает штатное повторение и затем перестраивает полный набор.
- `Pause studying` отключает активацию и маркер, не удаляя связи.
- При паузе карточки возвращаются из filtered deck в исходные колоды; при штатной остановке временная колода очищается и удаляется.
- После очистки сессии и закрытия Companion Connection ANKIGTA не закрывает Anki Desktop.
- После аварии сначала согласуется незавершённая Review Transaction, затем сессия очищается и перестраивается.
- При сбое CEF, перезапуске ресурса или переподключении MTA камера, курсор, управление, игровой звук и защита немедленно возвращаются к состоянию до открытия интерфейса.
- При закрытии Anki открытый Review Mode не восстанавливается автоматически; незавершённая Review Transaction сохраняется до ручного запуска Anki и последующей сверки.
- F7 и Review Mode автоматически повторно не открываются. Несохранённый текст формы теряется; подтверждённые изменения остаются в Change History.
- Прерванный Review Mode после переподключения не открывается; пользователь при необходимости сам начинает следующее повторение.
- Если оценка не отправлялась, Anki не изменяется. Если она была отправлена, companion add-on автоматически ремонтирует сессию и сверяет Review Transaction.
- Уже принятую оценку ANKIGTA подтверждает без повторной отправки; доказанно непринятую автоматически доотправляет с тем же `reviewTransactionId`.
- Пока результат неизвестен, сверка продолжается в фоне без слепой повторной оценки. Только эта карточка временно исключается из повторений; остальные остаются доступны.
- После подключения показывается текущее состояние восстановления: `Rating applied`, `Rating resent` или `Verifying rating`.
- Порядок восстановления: незавершённые Review Transaction → `ANKIGTA Session` → Activation Zone, статистика и маркер.
- Порядок смены коллекции: завершение либо сверка Review Transaction → очистка текущей `ANKIGTA Session` → пользователь переключает профиль в Anki → проверка Bound Anki Collection. `Outcome Unknown` запрещает переход.
- `Pending map save` после перезапуска не восстанавливается.
- Ручных команд создания и восстановления backup в F7 нет; если резервные копии создаются, это автоматический механизм сохранности.
- Перед каждой миграцией SQLite создаётся backup; после изменения данных дополнительный backup создаётся не чаще одного раза в сутки.
- Хранятся последние семь ежедневных и три предмиграционных backup. Они содержат SQLite целиком, но не connection config и не размещение UI.
- Backup записывается атомарно и не задерживает открытие F7.
- При повреждении основной базы показывается recovery-экран с доступными копиями; автоматического молчаливого отката нет.
- Пользователь выбирает копию, ANKIGTA проверяет и восстанавливает её, предварительно сохраняя повреждённую базу для диагностики.
- Облачной синхронизации и обычного управления backup в F7 нет.
- `Начать обучение` не запускает и не ожидает AnkiWeb sync; ANKIGTA использует текущее локальное состояние Bound Anki Collection.
- Ручной AnkiWeb sync во время активного обучения ставит ANKIGTA на паузу: неоценённая карточка закрывается без изменений, отправленная оценка завершается, filtered deck очищается. После sync пользователь запускает обучение заново.

### Settings ownership

- Server SQLite хранит Spatial Link, Map Entity metadata, Change History, `Include in study`, глобальный радиус по умолчанию, задержку автоматического открытия, порог скорости, activation mode, not-due policy, marker mode, Pause studying и Review Protection.
- Значение not-due policy по умолчанию — `Только Preview`; альтернативное значение — `Разрешить досрочное повторение`.
- Client MTA хранит язык, UI scale, клавиши, настройки громкости и медиа, заглушение игрового мира, блокировку управления и `Close after rating`.
- Companion add-on хранит порт прослушивания, токен и внутренние параметры совместимости Anki.
- MTA Server connection config хранит loopback-адрес, целевой порт и предъявляемый токен.
- Согласованная установка автоматически созданного токена является частью настройки соединения; секрет маскируется в UI и исключается из логов.
- Автоматически выбранный порт хранится согласованно с connection config обеих сторон; ручное значение является дополнительной настройкой.
- Связи и состояние `ANKIGTA Session` разделяются по коллекции Anki; остальные пользовательские настройки общие для коллекций.
- В v1 активна только Bound Anki Collection; другая открытая коллекция не получает отдельную игровую сессию и не использует сохранённые связи.
- Настройки подключения и размещение UI не входят в Change History; остальные пользовательские изменения входят.
- В v1 нет настроек на уровне отдельных колод или карт, кроме `Include in study` и уже определённых параметров Map Entity.
- Выбор профиля и начальный фильтр колоды доступны во встроенной настройке; фильтр колоды не является настройкой поведения отдельной колоды.

- Добавление нового языка не требует изменения Lua/CEF-логики.

### UI scale and window placement

- UI Scale задаётся числовым коэффициентом, а не процентами или ползунком.
- Допустимый диапазон — 0,5–2, значение по умолчанию — 1, шаг кнопок уменьшения/увеличения — 0,05; вручную вводится любое допустимое значение с точностью до двух знаков.
- Масштаб применяется сразу и записывается в Change History.
- Основные действия остаются доступны без горизонтальной прокрутки; внутренние панели могут прокручиваться, но закрытие и восстановление масштаба остаются видимыми.
- Интерфейс проверяется минимум на 1280×720, 1920×1080 и 3840×2160.
- F7 и Review Mode перетаскиваются за заголовок; Nearby HUD и Statistics HUD перемещаются только в режиме `Edit HUD layout`.
- Модальные предупреждения перемещаются вместе с родительским окном.
- Позиции сохраняются на клиенте в нормализованных координатах, но не входят в Change History.
- После смены разрешения, aspect ratio или UI Scale окна возвращаются в видимую область; часть заголовка всегда остаётся доступной.
- В настройках есть `Reset UI layout`.
- ANKIGTA поддерживает только клавиатуру и мышь. Геймпад не поддерживается и не планируется в будущих версиях.
- Подключённый геймпад не должен вызывать случайные действия или мешать CEF, но отдельная навигация, подсказки и переназначение для него не создаются.

### Map identity

- Карта имеет постоянный `ankigtaMapId`; переименование файла или ресурса не ломает связи.
- `ankigtaMapId` хранится как отдельный EDF custom child, а entity ID — как element data/EDF property в обычном MTA Map Editor.
- ANKIGTA не поставляет собственный fork Map Editor и не изменяет stock save lifecycle.
- При копии с тем же ID пользователь выбирает между переименованным оригиналом и новой копией; новая копия получает новые ID без автоматического переноса связей.
- Для Map Entity без сохранённого ID в F7 можно подготовить Spatial Link со статусом `Pending map save`.
- Pending Map Save не участвует в активации, `ANKIGTA Session`, статистике или маркерах.
- ANKIGTA не редактирует `.map` в фоне: пользователь сохраняет карту штатной командой Map Editor, после чего ANKIGTA автоматически обнаруживает изменение файла, повторно читает данные и активирует связь только после подтверждения `ankigtaMapId` и entity ID.
- Если автоматическая проверка не удалась, связь остаётся Pending Map Save и показывает действие `Проверить ещё раз`; оно повторяет только read-back и не записывает `.map`.
- Закрытие или перезагрузка карты без сохранения удаляет pending-связь с уведомлением.
- Stock Editor не гарантирует атомарность всей операции и может перезаписать внешнее изменение файла. ANKIGTA не обещает предотвращать это; после сбоя или неоднозначного read-back связь остаётся Pending Map Save, а пользователь повторяет сохранение либо использует штатный backup Editor.
- Метаданные уже идентифицированной Map Entity хранятся независимо от `.map` и не требуют сохранения карты.

### Link lifecycle

- Spatial Link создаются и заменяются только индивидуально; массового связывания, импорта таблицы связей и batch editing метаданных нет.
- Массовые изменения карточек выполняются в Anki и автоматически отражаются в ANKIGTA для уже существующих Spatial Link.
- Явный `Unlink` требует подтверждения с указанием Map Entity и карточки.
- `Unlink` удаляет только Spatial Link: Map Entity, её имя, теги и радиус сохраняются, а Anki Card не изменяется.
- Если Review Mode уже открыт, он завершается по прежним правилам; отвязанная карточка исключается из следующего пересчёта очереди.
- Пользовательские изменения данных ANKIGTA, включая Spatial Link, метаданные Map Entity, `Include in study` и пользовательские настройки, записываются в единую сохраняемую Change History последних 100 операций.
- Настройки подключения, размещение UI, оценки и расписание Anki, runtime-события игрового мира, автоматически назначенные ID и миграции в Change History не входят.
- Undo и Redo используют Change History и не исчезают при закрытии F7 или перезапуске ресурса.
- Новое изменение после Undo удаляет оставшуюся ветку Redo.
- Позднее Map Entity можно снова связать с любой карточкой обычным `Link`.
- `Card missing` и `Object missing` не являются явным `Unlink`: их записи сохраняются для восстановления.
- Для уже связанной Map Entity доступно отдельное действие `Replace card`, не требующее промежуточного `Unlink`.
- Подтверждение `Replace card` показывает старую и новую карточки. Повторное использование карточки разрешено после предупреждения со списком других связанных сущностей.
- Открытый Review Mode со старой карточкой завершается; новая карточка входит в `ANKIGTA Session` после закрытия и пересчёта.
- Для `Card missing` используется то же действие `Replace card`.
- Статус отсутствующей сохранённой сущности называется `Entity missing`, поскольку он применяется к object, vehicle и ped; уничтоженная Runtime Instance не создаёт этот статус.
- `Relink entity` позволяет выбрать для записи `Entity missing` живую Map Entity через список или `Pick object`, включая сущность из другой загруженной карты или другого `interior/dimension`.
- Целевая Map Entity должна быть без Spatial Link. Её собственные `ankigtaMapId` и entity ID сохраняются, а старая идентичность ей не присваивается.
- Со старой записи переносятся Spatial Link, имя, теги, радиус и `Show radius`; подтверждение предварительно показывает сравнение метаданных.
- После переноса старая missing-запись удаляется из активного списка, не создавая дубликат.
- `Relink entity` записывается в Change History и полностью отменяется; открытый Review Mode завершается до пересчёта.

### Statistics

- Название общего счётчика — `Total`, не `Remaining`.
- New — все уникальные новые карточки, связанные с Active Map Set; исходные дневные лимиты Anki не исключают их из `ANKIGTA Session`.
- Learning — уникальные learning/relearning карточки, доступные сейчас.
- Due — уникальные review-карточки, доступные сейчас и достигшие срока.
- Early — уникальные Not-due Card, включённые настройкой `Разрешить досрочное повторение`.
- Total — объединение New, Learning, Due и Early.
- `Early` показывается всегда; при выключенной настройке или отсутствии досрочных карточек его значение равно `0`.
- Повторная связь одной карточки с несколькими сущностями не увеличивает счётчики.

### Performance envelope

- Эталонная среда v1: Windows-компьютер с 4-ядерным процессором, 16 ГБ RAM и SSD при одновременно запущенных MTA и Anki.
- Поддерживаемый проверочный объём: 10 000 Map Entity в загруженных картах, 5 000 Spatial Link и 100 000 карточек в коллекции Anki.
- F7 становится доступен не позднее 2 секунд; поиск и фильтрация реагируют не дольше 150 мс.
- Pick Entity, Activation Zone и HUD добавляют не более 2 мс к среднему времени кадра.
- Первая страница Card Picker, открытие карточки и подтверждение оценки укладываются в 1 секунду в 95% локальных запросов.
- Полная перестройка `ANKIGTA Session` для 5 000 связей занимает не более 5 секунд; интерфейс остаётся доступным и показывает прогресс.
- CEF никогда не загружает все 100 000 карточек целиком.
- Превышение проверочного объёма может замедлять работу с предупреждением, но не должно приводить к потере данных.

### Definition of Done for v1

- Все шесть обязательных технических прототипов дали положительный результат либо архитектура изменена с учётом их фактических выводов.
- Автоматически проходит end-to-end сценарий `Map Entity → Spatial Link → Activation Zone → question → answer → rating → новая очередь`.
- Есть автоматические тесты идемпотентности оценки, восстановления после сбоев, миграций SQLite и Change History.
- Проверены состояния new, learning, relearning, review, suspended, buried, not-due, Card missing и Entity missing.
- Установка, обновление, пауза и удаление ANKIGTA не оставляют карточки застрявшими в `ANKIGTA Session`.
- Нет известных дефектов, способных повредить расписание Anki, `.map`, SQLite или потерять Spatial Link.
- Пройдены утверждённые performance-тесты.
- Документированы установка, совместимые версии, резервное копирование, восстановление и удаление.
- Обязательный функционал не требует ручного редактирования SQLite или `.map`.
- Установка и обновление companion add-on выполняются пользователем по документации; это не считается ручным редактированием данных Anki.
- Визуальная полировка и мультиплеер не блокируют выпуск v1; геймпад и любые массовые операции ANKIGTA исключены.

## Confirmed but not yet concrete enough to implement

- Для постоянных ID принят best-effort workflow вокруг обычного MTA Map Editor: EDF custom child для map identity, element data/EDF для entity ID, блокировка дублей и автоматический независимый read-back после штатного Save с ручным действием `Проверить ещё раз`. Отдельный fork, атомарность всей save transaction и защита от внешнего изменения файла не требуются. End-to-end сценарии ещё нужно проверить.
- Filtered deck и Exact Card Admission доказаны для Anki 26.05; все связанные новые карточки допускаются независимо от исходных дневных лимитов, с явным предупреждением для карточек сверх сегодняшнего лимита.
- Server-side Lua и companion add-on имеют утверждённые роли; production API и восстановление вокруг X-only/full rebuild ещё нужно специфицировать.
- Для предупреждения о превышении дневного лимита нужен проверенный способ отличать обычную доступность новой карточки в исходной колоде от её допуска через exact filtered deck; собственный scheduler для этого создавать нельзя.
- Durable Review Transaction journal доказан на границах Prototype 0003, но production storage, garbage collection, native transaction receipt и crash внутри атомарной backend-операции остаются недоказанными.
- Add-on-owned collection UUID принят. Для коллизии копии выбран явный Collection Copy Decision; техническое обнаружение и атомарное назначение нового UUID ещё нужно доказать.
- Автоматическое in-process переключение профиля опровергнуто; принят ручной fallback: ANKIGTA не запускает Anki и не меняет профиль.
- Немедленное закрытие standard Reviewer после начала rating опровергнуто. Принят безопасный fallback: дождаться штатного callback, затем закрыть и запустить сессию; закрытие Reviewer остаётся version-gated.
- Реальный IPv4 loopback transport, LAN isolation, token validation, reconnect и auto/manual port behavior доказаны Prototype 0004. Для v1 принят единственный transport path `127.0.0.1`; несовместимый IPv6 `::1` исключён.
- Для production connection config выбран authority: companion add-on публикует файл в однажды указанную папку MTA-ресурса, а MTA читает его; обе стороны имеют advanced manual override. Manual mismatch завершается явной ошибкой без автоматического победителя. Локальный компьютер доверен, поэтому специальное шифрование не требуется. Commit/recovery contract с одной предыдущей рабочей версией определён продуктово, но ещё требует технического доказательства.
- Для production transport принят предел control JSON 2 MiB; тяжёлые HTML/media идут через отдельный read-only content endpoint. Приняты обычный timeout 5 секунд, один identical retry для чтений и 30 секунд для session rebuild; rating после неопределённого исхода только сверяется. Ещё не выбраны streaming/range/cache, per-media limits, backpressure и latency targets.
- Статистические категории названы, но ещё не доказано, что companion add-on может получать их без расхождения со штатным планировщиком.
- Прямой Teleport определён продуктово, но нужны точные правила для динамической и отсутствующей сущности при гонке состояний.
