# Allow an optional connection token on the same host

Поскольку Anki, companion add-on и MTA Server в v1 находятся на одном компьютере, токен подключения необязателен. Пустой токен разрешает работу с закрываемым предупреждением; если токен настроен, его значения на стороне MTA Server и companion add-on должны совпадать.

При первой настройке companion add-on по умолчанию генерирует криптографически случайный токен и после однократного выбора папки MTA-ресурса атомарно публикует connection config для MTA Server; пользователь не переносит секрет вручную. Пустой токен возникает только после явного отключения защиты пользователем. В дополнительных настройках companion add-on и MTA доступны поля для ручной замены токена и порта на случай диагностики или восстановления. Существующий токен не раскрывается: поле маскируется и принимает новое значение; секрет никогда не записывается в диагностические логи.

v1 доверяет локальному Windows-компьютеру и другим работающим на нём программам. Токен предотвращает случайные запросы и отделяет карточный CEF от control API, но не является защитой от локального администратора, вредоносной программы или процесса с доступом к файлам ANKIGTA. Специальное шифрование локального connection file не требуется; достаточно не показывать секрет в обычном UI, не писать его в логи и использовать обычные ограниченные права файла.

Companion add-on в v1 привязывает listener только к numeric IPv4 loopback `127.0.0.1`. Prototype 0004 подтвердил этот путь и недоступность listener через LAN-адрес. Рабочий Windows/Python listener на `::1` не был доступен из MTA `fetchRemote`, который вернул status `6`, поэтому IPv6 в v1 явно не поддерживается и отдельного fallback не имеет. Подключения через LAN, внешний сетевой интерфейс или интернет не поддерживаются и не могут быть разрешены токеном или настройкой.

Loopback-порт по умолчанию выбирается автоматически. При занятом порте ANKIGTA выбирает другой свободный порт и восстанавливает соединение. Ручной ввод порта остаётся доступен только в дополнительных настройках.

Companion add-on является владельцем автоматически создаваемой connection config. MTA Server читает атомарно опубликованный локальный connection file из своего ANKIGTA resource; этот файл не является пользовательским интерфейсом и не требует ручного редактирования.

Ввод ручного порта или токена включает Manual Connection Mode только на той стороне, где сделан ввод. Автоматическая публикация не перезаписывает ручное значение. Если effective port/token двух сторон расходятся, соединение не устанавливается и показывает явную ошибку конфигурации; ANKIGTA не угадывает правильную сторону и не исправляет расхождение молча. Пользователь либо задаёт одинаковые ручные значения на обеих сторонах, либо явно возвращает обе стороны в Automatic Connection Mode.

При публикации automatic connection config companion add-on сохраняет ровно одну предыдущую подтверждённо рабочую версию. Новая версия сначала полностью записывается во временный файл, проверяется и только затем атомарно заменяет текущую. MTA проверяет формат, версию и protocol identity; повреждённая либо неподтверждённая новая версия отклоняется, после чего используется предыдущая рабочая конфигурация и показывается ошибка применения настроек. Если обе версии непригодны, Companion Connection остаётся отключённым до исправления настроек.

Prototype 0004 подтвердил выбор следующего свободного порта, protocol identity, token validation, ручной override и ошибки occupied/range/external-bind. Его orchestrator передавал выбранный порт обеим сторонам, поэтому production atomic publication/storage конфигурации остаётся недоказанной.

HTTP success сам по себе не является protocol success: companion response принимается только после проверки Content-Type, JSON schema, required fields и совпадения `requestId`/`reviewTransactionId`. Protected mode проверяет токен до dispatch и не сохраняет его в логах. Явно отключённый токен технически работает, но остаётся ослабленным режимом с предупреждением.

Обычный control request имеет timeout 5 секунд. Read-only request после временной транспортной ошибки автоматически повторяется не более одного раза с тем же `requestId`. Timeout освобождает игровой интерфейс; automatic reconnect продолжается в фоне и сам не запускает обучение. Длительная операция перестройки `ANKIGTA Session` имеет отдельный timeout 30 секунд, остаётся отменяемой и показывает прогресс.
