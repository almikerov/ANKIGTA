# Use a bounded persistent Change History

ANKIGTA хранит единый журнал последних 100 пользовательских изменений своих данных и настроек, поддерживающий многошаговые Undo и Redo между перезапусками. Новое изменение после Undo удаляет оставшуюся ветку Redo; параметры подключения, размещение UI, оценки Anki, runtime-события, автоматически назначенные ID и миграции не журналируются, чтобы не откатывать секреты, эфемерное представление, внешнее состояние или системную целостность. ADR 0028 сузил это правило: журналируется только то, чем владеет сервер, потому что история живёт в его базе, — а значит все клиентские настройки, не только размещение UI, остаются вне истории.
