# Keep Anki authoritative for study data

Anki владеет содержимым, шаблонами, CSS, медиа, Anki Tag, колодами, расписанием и доступностью карточек; ANKIGTA владеет Spatial Link и игровыми метаданными. Изменения Anki автоматически отражаются в существующих связях, но обратно передаются только оценки; новый `cardId` никогда не сопоставляется со старой карточкой эвристически.

Колода, выбранная во встроенном Card Picker, является только начальным фильтром. Spatial Link опирается на Anki Card Identity, поэтому перенос карточки между колодами не отключает связь.

ANKIGTA не управляет AnkiWeb: не запускает облачную синхронизацию, не ждёт её перед началом обучения и не хранит её настройки. Пользователь синхронизирует коллекцию штатными средствами Anki, а ANKIGTA работает с текущим локальным состоянием Bound Anki Collection.

Если пользователь запускает штатную синхронизацию во время активного обучения, AnkiWeb sync имеет приоритет. ANKIGTA закрывает неоценённый Review Mode без изменения карточки, завершает уже отправленную Review Transaction, очищает filtered deck и остаётся на паузе. После окончания синхронизации игровое обучение автоматически не возобновляется.

Prototype 0002 подтвердил эту границу на Anki 26.05: ANKIGTA формировала и перестраивала filtered deck, но состояние карточек и `revlog` изменял только штатный планировщик Anki. Прямые SQL-записи, private queue mutation и собственный scheduler не допускаются.

Prototype 0003 сохранил эту границу при durable recovery: journal принадлежал coordinator, а фактическое расписание и `revlog` изменял только Anki. Reconciliation читает полные дельты, но не использует SQL как production write path и не считает `revlog` timestamp идентификатором транзакции.
